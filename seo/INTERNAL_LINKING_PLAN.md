# INTERNAL_LINKING_PLAN.md — Hub-and-Spoke (anchors as nodes)

Architecture: Home (hub) → services.html anchors (spokes) → proof (portfolio/brands) → conversion (contact). Informational (future) → spoke + proof + contact. Footer = safety net (already complete). Anchor text: natural variations, never sitewide exact-match.

## Node roles

- `/` hub: 8 service cards (exact anchors, one each — live), FAQ contextual links (live: 6 keyword links), footer.
- `services.html` spokes: `#growth-consulting #performance-marketing #website-seo #content-production #social-media #influencer-marketing #ai-content #bundle`. FAQ answers cross-link spokes (live: 14 contextual links). Page-CTA → contact (live).
- `portfolio.html` proof: noscript brand list, FAQ → services anchors + contact (live: 6 links), CTA → contact.
- `brands.html` proof: logo grid → add (APPROVED): intro line linking `#influencer-marketing` (creator-led brands) + `#content-production` (ad films); CTA → contact already.
- `contact.html` conversion: form service options mirror 8 spokes (live); FAQ links home/services/portfolio (live).
- `blog/research/community/newsletter/partnerships/careers`: footer-linked; future articles must each link ONE spoke + portfolio + contact (rule for M10).

## Anchor-text rotation (examples, already applied)

- performance: "Meta ads" / "performance marketing" / "retargeting" (never "best meta ads agency" sitewide).
- influencer: "influencer network" / "influencer marketing" / "110+ YouTubers".
- seo: "Website + SEO" / "technical SEO" / "content strategy".
- geo: "Kolkata, India" / "across India" (NAP stays byte-identical everywhere).

## Anti-patterns enforced

- No exact-match anchor repeated in footers/cards (cards use service names once — acceptable as navigation, not manipulation).
- No links to non-targets (no google-ads/ppc/city pages exist to link to).
- No orphan pages: every public page already in footer + sitemap; video/inspo/manage intentionally orphaned from link graph (noindex).
